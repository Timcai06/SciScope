> 状态：**已冻结**（2026-08-04）  
> 上游：`charter.md`、`roadmap.md`、多轮目标讨论结论  
> 用途：之后一切开发、报告改写、演示与提交的**唯一目标上游**。与本文冲突时，先改代码/文档，或显式修订本说明书并记一笔变更。

---

## 0. 一句话目标

把 SciScope 做成**可被调用的科学证据基础设施**：对内能判定支持/反驳/不足并沉淀争议（stance **L3**），对外以 API/MCP 作为**文献数据要素服务**出口，并以**本机全量**工作流证明能用；提交侧用**评委视频 + 硬件清单**双轨保障复现理解。

成功排序（目标函数，不是口号）：

1. 技术护城河进阶（stance L3 可证）
2. 可演示产品（本机全量黄金脚本）
3. 可被调用（MCP tools + resource + **OpenCode** 真调一次）

国奖名次是结果，不写入目标函数。

## 1. 叙事结构（综合评委）

| 层 | 角色 | 评委听到的话 |
|---|---|---|
| **C 价值壳** | 开场 / 效益章 | 公开科技文献 → 可治理数据要素 → 可计算、可调用的证据服务（贴出题单位） |
| **A 技术魂** | 技术章主干 | 不是“相关即支持”，而是证据句级 stance + 校准拒答 + 争议地图 |
| **B 展示皮** | 演示与系统章 | Go TUI 消费 SSE 的完整科研工作流；智能只在 Python 内核 |

创新点只保留三个（报告与答辩禁止再堆）：

1. 文献数据要素分层治理与可复现资产链  
2. 论断级 stance L3 与争议沉淀  
3. 协议化证据后端（API / SSE / MCP），界面可替换

## 2. 成功度量（做成什么样算达标）

### 2.1 护城河 — Stance L3

| 项 | 达标定义 |
|---|---|
| 证据句定位 | 每条采用的证据能落到句级（或等价最小跨度），不只整段摘要 |
| 标签体系 | SUPPORT / CONTRADICT / NEUTRAL；聚合 verdict 可解释 |
| 校准与拒答 | 低置信必须倾向「证据不足」；有拒答/置信表现（曲线或分桶表） |
| 限定条件 | 人群/剂量/时间/物种等明显冲突时降级为 NEUTRAL 或证据不足，并写出理由 |
| 回退纪律 | LLM 不可用时仅 similarity → **不得**输出「强支持」类措辞 |
| 对称性 | 论断 C 与 ¬C 不得无理由同判为支持 |
| 金标准评测 | 见 §3；主表进项目报告与 `output/eval/` |
| 对照 | 与纯 similarity baseline 同集对比，报告必须展示 |

### 2.2 争议地图

- 权威源：`claim_evidence_stance` + `contradictions`（或后继等价物）  
- **三条读路径全通**：HTTP API、Agent tool、MCP resource  
- 演示中：现场核查后，争议列表能读到同一 claim  

### 2.3 可调用 — MCP + OpenCode

- MCP：**tools + 至少一个 resource**（争议前线，名称可实现时定，语义不变）  
- 外部 agent **固定为 OpenCode**（开源、可复现调用链）  
- 提交产物必须包含：调用步骤说明 + 日志或录屏 + 返回摘要（进报告附录/examples）  
- 定位句统一：*SciScope = 科研 agent 的证据后端 / 文献数据要素服务层*  

### 2.4 可演示 — 本机全量

- 现场/录屏主路径：**仅本机全量库**（非 hosted 220 篇）  
- 黄金脚本跑通：规模可见 → 证据问答 → L3 核查（正/反/限定/拒答）→ 争议列表 → OpenCode MCP 调用  
- doctor/失败原因可解释，禁止 silent empty success  
- hosted 若保留：文档明确「公开小样本入口 ≠ 国赛能力全集」  

### 2.5 交付与叙事

- **项目报告 + 数据分析报告**均同步为「要素治理 → 服务化」表述（不只改项目报告）  
- 四套数字永远分开：原始 / 分析 / 处理语料 / 运行库实测  
- 诚实边界专节：全文覆盖与 PMC 偏向、趋势/推荐非主叙事、L3 非临床诊断级

## 3. 金标准范围（S1 裁定）

**原则：可辩护优先于规模；双语主集 + 公开协议锚点。**

### 3.1 主集（必做，报告主表）

- **自建双语 claim–evidence–stance 金标准**  
- 覆盖三大赛题领域：计算机科学、生物医学、材料科学  
- 中英均有；每条含：claim、证据句（或句 span）、标签、可选限定条件标记  
- 规模以标注质量为准：建议 **80–150 条 claim**（可阶段性扩大，但不以刷数代替一致性）  
- 标注规范书面化（一人主标 + 抽检一致性，或双人协商），进 `evaluation/` 或 `docs/`  

### 3.2 锚点集（必做，方法可信度）

- 采用 **SciFact（或同协议子集）式公开事实核查设定** 作英语方法锚点  
- 用途：证明 stance 管线不是「只在自家标签上自嗨」  
- 做法二选一（实现期定，目标层都承认）：  
  - A. 在可对齐到本库或可引用的公开摘要/全文上跑同一套句级 stance 协议；或  
  - B. 固定 SciFact 官方划分的子集，报告 protocol 对齐说明与分数，并诚实写清语料重叠边界  
- **不**以刷 SciFact SOTA 为国赛目标；锚点服务于「方法可对照」  

### 3.3 不做

- 不扩自身 16 万语料只为凑金标准  
- 不把标题自检索 Recall 当 stance 主结果  
- 无人工规范就自动生成假金标准并当正式结果

## 4. 演示与复现双轨（S4）

| 轨 | 内容 | 目的 |
|---|---|---|
| **评委视频** | 按 §6 剧本录制本机全量 + OpenCode 调用 | 综合评委 10 分钟内建立信任 |
| **硬件/环境清单** | CPU/RAM/磁盘、PostgreSQL/pgvector、模型路径、耗时量级、关键 `make` 命令 | 说明全量可复现的门槛，避免“不可复制的魔法” |
| **文档复现** | runbook 逐步：安装 → 起库 → 加载 → 启动 → 黄金脚本 | 格式规范分；与视频口径一致 |

现场若环境不允许全量，**仍以视频为能力举证**；口头不切换到 hosted 冒充全量。

## 5. 技术主线：做 / 不做 / 可延后

### 5.1 做（允许大改）

1. Stance L3 管线（句级、校准拒答、限定条件、回退纪律）  
2. 金标准主集 + SciFact 协议锚点 + similarity 对照  
3. 争议地图 API / Agent tool / MCP resource  
4. MCP 扶正；OpenCode 外部真调产物  
5. 本机全量演示底座与黄金脚本  
6. 项目报告 **与** 数据分析报告的要素服务化改写  
7. 评委视频 + 硬件清单 + 复现文档对齐  

### 5.2 不做

- 扩语料、加数据源  
- 重启 Web 工作台；智能写入 Go TUI  
- 趋势/推荐算法竞赛化（保留赛题能力与诚实指标即可）  
- 为演示造第二套假数据路径  
- hosted 小库充当国赛主演示  
- 无评测宣称「生产级科学核查 / SOTA」  

### 5.3 可延后（不进本说明书承诺）

- 全库后台「科学天气预报」扫描  
- 多租户鉴权、完整 OTel、SBOM 生产治理  
- 公开全量 CDN 分发  
- 中文 FTS 分词大改（仅当评测证明检索是 L3 主瓶颈时再开）

## 6. 黄金演示剧本（本机全量，约 6–8 分钟）

1. **C 开场（30s）** — 文献要素治理 → 证据服务  
2. **规模一屏（30s）** — 运行库论文/chunk 与报告口径一致  
3. **B 基线（90s）** — 真实问题 → `[n]` 证据问答 → 证据卡  
4. **A L3（150s）** — 正论断 / 反论断 / 限定冲突 / 证据不足  
5. **争议地图（60s）** — 列表读到刚写入的矛盾 claim  
6. **OpenCode 调用（90s）** — MCP `verify_claim` + disputes resource  
7. **收束（30s）** — 三创新点 + 一句诚实边界  
8. **备用** — 趋势或推荐各一问（证赛题功能，不展开）

- 概述/创新/方案/价值四章对齐 §1 叙事

## 8. 外部 Agent 固定（S2）

| 项 | 决定 |
|---|---|
| 选型 | **OpenCode**（开源，调用链可审计、可写进复现） |
| 方式 | 经 MCP 连接 SciScope server；至少 exercise 1 个核查 tool + 1 个争议 resource |
| 产物 | 步骤文档 + 日志/录屏 + 报告附录引用 |
| 禁止 | 仅用闭源商业 agent 作为唯一举证而无法提供可复现步骤 |

## 9. 答辩不可被问穿的三件事

1. **Stance 是否 LLM 自说自话？** → 金标准、对照、句级证据、回退纪律、边界表述  
2. **演示与可复现是否同一套能力？** → 本机全量视频 + 硬件清单 + 文档；hosted 不顶替  
3. **“数据要素/可调用”是否只有 PPT？** → OpenCode MCP 真调产物 + 服务口径  

预埋诚实句：全文 10% 级且偏 PMC；趋势/推荐非主叙事；L3 非临床或监管级结论。
