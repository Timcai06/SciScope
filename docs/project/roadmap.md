## 历史执行记录（已完成，压缩保留）

以下为 2026-07 前的执行记录，均已实现并验证；细节不再在本文件维护，
稳定事实见对应 canonical 文档与 `output/eval/`。

### 第 0 步 — 先证明缺陷 ✅ 已完成

写 `xfail(strict=True)` 测试钉住缺陷：`verify_claim` 对一句论断及其否定此前都判
"强支持"（相似度判的是"相关"不是"蕴含"）。落点：`backend/tests/test_verify_claim_stance.py`。

### 第 1 步 — 给 verify_claim 加 stance 层 ✅ 已完成

对每条检索证据用 LLM judge 判定 SUPPORT/CONTRADICT/NEUTRAL，verdict 由立场标签聚合，
新增"证据反驳、存在争议、证据立场统计"；judge 不可用时回退相似度且**只报证据不足**。
落点：`backend/app/agent/tools/verify_claim.py`；全套后端测试通过。

### 第 2 步 — 矛盾即资产 ✅ 已完成

每次 L3 核查把全部已判定证据 upsert 到 `claim_evidence_stance` 表，`contradictions`
视图派生"同时有支持与反驳"的论断——**争议地图的种子，随核查自己生长**。
落点：`infra/postgres/stance.sql`、`backend/app/services/stance/store.py`、`verify_claim.py` 接入。
验证：真实链路核查落库；视图与改判语义经事务测试。

### 插曲 — 产品力打磨（2026-07，已收敛）✅ 已完成

第 2 步与第 3 步之间进行的产品对话质量打磨（提示层、体验驱动、检索去重、趋势忠实、
对话质量回归评测）已收敛：`evaluation/eval_dialogue.py` 7 场景 18 检查点，首轮 4/7、
修复后 **7/7**（`output/eval/dialogue_report.md`，复现 `make eval-dialogue`）。关键修复
之一是消除"把证据不足的诚实结论逼成明确支持"的确认偏误。此段过程不再在此维护。

## 不做什么（同样重要）

- 不再扩语料、不堆已成熟的"检索/趋势/推荐"红海功能。
- 不重启 Web 前端作为主线（若做，按新范围单独立项）。
- 不把智能焊进任何界面；不做"又一个通用助手"。
- 不把已实现的实现基础（L3/争议/MCP）在未完成金标准与外部证据前包装成"已证明"。
