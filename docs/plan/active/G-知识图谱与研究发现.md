- 负责人：检索/图谱负责人；复核：项目负责人 + 领域专家

## 原子任务

### G00｜冻结图谱、推荐与趋势基线

- 状态：`PENDING`；依赖：无。
- 只读范围：`backend/app/services/{graph_service,recommend_service}.py`、`backend/app/agent/tools/`、
  `output/graphs/`、数据库运行态。
- 验收：分别记录图谱 JSON 版本、节点/边来源、推荐所需 embedding 表、趋势数据窗口和各自
  可用/不可用状态；环境未启动只能标 `BLOCKED`，不得猜测成功。
- 验证：保存一次健康检查、只读查询或明确的阻塞记录。

### G01｜可追溯知识图谱资产

- 状态：`PENDING`；依赖：G00、D02。
- 文件所有权：图谱构建脚本、`output/graphs/` 的生成说明、图谱测试；不改 TUI。
- 做什么：为节点和边增加来源论文、构建版本、关系类型、权重含义和缺失/去重规则；区分
  “共现关系”与“支持某科学结论”，后者只能由 E 线 L3 给出。
- 验收：任一展示关系能追溯至论文/字段；生成脚本可在小样例重复运行；共现不被显示为因果。
- 验证：小样例重建、关系回链抽样、schema 测试。

### G02｜图谱、推荐、趋势的查询解释合同

- 状态：`PENDING`；依赖：G01。
- 文件所有权：`backend/app/services/`、`backend/app/agent/tools/`、对应 API/Agent 测试与文档；
  事件消费改动交给 T 线。
- 做什么：统一输出实体、关系/相似理由、时间范围、数据版本、来源论文和不可用原因；把
  “相关文献推荐”与“研究方向辅助”分开，方向只给可回溯趋势/空白线索，不给无证据创新断言。
- 验收：三个查询各有成功、空结果、依赖缺失的结构化响应；无 embedding 时明确降级。
- 验证：契约测试与三条固定查询产物。

### G03｜全量向量、重排与推荐可用性

- 状态：`BLOCKED`；依赖：2080 Ti 恢复、G00。
- 文件所有权：embedding/retrieval/recommend pipeline、评测配置；笔记本不得执行全量构建。
- 做什么：在远程机断点续跑全量 embedding，必要时完成 reranker 构建；记录模型、硬件、索引
  版本、耗时、失败恢复和成本。
- 验收：全量 `paper_embeddings` 与必要 chunk 向量具有清晰覆盖率；推荐接口在运行环境有真实
  成功记录，而不是 mock。
- 验证：仅在远程机执行 `rtk make embeddings` 及约定的运行时烟测；把实际命令、版本和退出码
  写回。2080 Ti 不可用时不得移除 `BLOCKED`。

### G04｜推荐、趋势和方向辅助评测

- 状态：`PENDING`；依赖：G02；若评测依赖全量向量，还依赖 G03。
- 文件所有权：`evaluation/`、评测样本、报告图表；不改金标准 stance 标注（归 E01）。
- 做什么：为推荐建立相关性、多样性、新颖性和用户盲评；为趋势采用滚动时间切分并和 naive
  比较；方向卡只在这些证据成立时使用。
- 验收：推荐/趋势均有基线、分母和失败案例；若趋势不能超过 naive，降级为描述性趋势。
- 验证：固定切分的评测脚本和可重建结果表。
