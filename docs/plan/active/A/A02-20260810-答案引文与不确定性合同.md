- 归属：A 线「科研问答与协议」第三个原子任务；依赖 A01、D05、E02。
- 文件所有权：Agent 输出 schema、SSE 事件、API 聚合、`verify_claim` 合同与测试；**不改 TUI 渲染**、不改 E/G 线文档。

## 一、做了什么

在不新增第二套 Agent loop、也不改 TUI final payload 字符串行为的前提下，补了一层统一的
`answer-contract/v1`：

1. **新增共享 schema**
   - `backend/app/models/schemas.py`
   - `AnswerCitation` / `AnswerUncertainty` / `StructuredAnswer`
   - 统一表达：结论状态、引文、chunk 级 provenance、不确定性、是否退化为
     `generative_non_evidentiary`

2. **新增合同归并器**
   - `backend/app/agent/answer_contract.py`
   - 从已执行 tool result 派生统一 `structured_answer`
   - 当前优先消费 `verify_claim`，并对依赖故障、缺失 tool result、无引文关键结论做 fail-closed 标记

3. **`verify_claim` 原生输出结构化合同**
   - `backend/app/agent/tools/verify_claim.py`
   - 各分支都返回 `structured_answer`
   - 明确区分：
     - `not_found`：未检索到相关文献
     - `evidence_insufficient`：检索到相关证据但不能采信为支持/反驳
     - `abstained`：judge 不可用，仅 similarity 回退
   - 引文补 `chunk_uid` / `source_field` / `evidence_sentence`

4. **Agent final event / `/api/agent` 聚合挂载**
   - `backend/app/agent/langgraph_runtime.py`
   - `backend/app/agent/events.py`
   - `final` 事件仍然把用户可见答案放在 `payload`
   - 结构化合同放在 `meta.structured_answer`
   - `run_agent()` 聚合结果同步带 `structured_answer`

5. **检索补 chunk 级 provenance**
   - `backend/app/services/retrieval_service.py`
   - `RetrievedPaper` 新增 `chunk_uid` / `source_field`
   - `verify_claim` 现在能把 top chunk 的 provenance 带进 L3 证据

## 二、统一合同

核心字段：

- `schema_version`: `answer-contract/v1`
- `capability`: `claim_verification` / `general_research_answer`
- `status`:
  - `supported`
  - `partially_supported`
  - `contradicted`
  - `disputed`
  - `not_found`
  - `evidence_insufficient`
  - `abstained`
  - `dependency_failure`
  - `not_applicable`
- `answer_mode`: `evidence_based` / `generative_non_evidentiary`
- `citation_compliance`: `ok` / `missing_required_citations` / `not_applicable`
- `citations[*]`: `paper_id + title + year + chunk_uid + source_field + evidence_sentence + stance + confidence`
- `uncertainty`: `category + message + calibrated_rejection + qualification_hints`

关键纪律：

- 关键证据结论若最终中文回答里缺少 `《标题》(年份)`，即使 tool 有证据，也自动降为
  `generative_non_evidentiary`
- tool 缺结果 / 执行报错 / 未授权 / 未执行，统一归 `dependency_failure`
- similarity-only 回退永远是 `abstained`，不伪装成支持或反驳

## 五、复核修复（2026-08-10）

针对独立复核的两条修改：

1. **citation gate 不再只识别 `《标题》+年份`**
   - 现在支持至少：
     - `《标题》(年份)`
     - `标题 (年份)`
     - `标题（年份）`
     - `标题, 年份`
     - `标题，年份`
   - 同时加了负例，避免把较短标题误判成较长标题的子串命中

2. **malformed embedded `structured_answer` 改成 fail-closed**
   - `verify_claim` 若返回坏形状的嵌入合同，不再让 `model_validate` 直接炸
   - 先尝试从外层 `verify_claim` payload 安全重建
   - 若连重建都只能落到无意义的 `not_applicable`，直接转 `dependency_failure`
