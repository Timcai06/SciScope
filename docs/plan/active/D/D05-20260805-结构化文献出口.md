## 2. 输入 / 输出 schema

**输入**：D03 `data/admission/structured/structured.jsonl` + D01 `data/admission/staged.jsonl`（提供 license/usage_rights）。

**输出**（schema `structured-export/v1`）：

```jsonc
{
  "schema_version": "structured-export/v1",
  "paper_id": "PX-DEMO",
  "source": "iflytek",
  "record_sha256": "…",
  "license": "cc0",
  "usage_rights": "snippet",                 // indexable | snippet | redistributable | unknown
  "display_policy": {"authorized": true, "reason": "usage_rights_allows_display"},
  "fields": [
    {"field": "main_result", "status": "extracted", "confidence": 0.8,
     "value": "…", "evidence": {"chunk_uid": "…", "locator": {…}, "sentence": "…", "span": {…}}},
    {"field": "limitations", "status": "not_found", "value": null,
     "reason": "…", "pending_candidates": ["…"]}   // 未抽取不作为事实
  ]
}
```

三类边界（评审要求的核心）：

| 情形 | 表达 |
|---|---|
| **未抽取**（not_found / low_confidence） | `value=null`，status 明确；低置信附 `pending_candidates` 待审；不作为确定事实 |
| **未授权展示**（usage_rights=indexable / unknown） | `display_policy.authorized=false`；已抽取字段 `value=null` + `display="not_authorized_display"`（定位与置信度仍返回，供索引与审计）；unknown 一律保守拒绝 |
| **无来源字段** | 仅 `status=extracted` 且带 evidence 的字段有 value；来源缺失即非事实 |

`source` 缺省且多来源同名 paper_id → 返回 `multiple_sources` + `matches`（不猜测唯一来源）。

## 修复记录（2026-08：未授权正文泄露）

### 缺陷

`_field_view()` 对 extracted 字段**无条件返回 evidence**：当 `usage_rights=indexable` 或
`unknown` 时虽 `value=null`，但 `evidence.sentence` 仍含原文证据句（且 span/精确 offset
可协助复原正文），`pending_candidates` 也返回原文候选句；`paper_structured` tool 原样暴露。
违反“未知许可不得展示正文片段”的 D01/D05 边界。

### 修复

| 许可 | value | evidence.sentence/span | pending_candidates | 返回的审计信息 |
|---|---|---|---|---|
| snippet / redistributable | ✅ 返回 | ✅ 完整 provenance | ✅（低置信字段） | — |
| indexable | ❌ null | ❌ 移除 | ❌ 移除 | `audit={chunk_uid, locator_type, confidence}` + `display=not_authorized_display` |
| unknown（保守） | ❌ null | ❌ 移除 | ❌ 移除 | 同上（`usage_rights_unknown_conservative`） |

- 未授权时 `audit.locator_type` 仅保留 D02 白名单中的**粗粒度 base 类型**，
  不含 `field`、页码、`start_char`/`end_char` 等可复原正文的定位细节；
- 复核强化：`audit.locator_type` 仅允许 D02 的固定 locator base，`chunk_uid` 仅允许
  D02 的 40 位 SHA-1 不透明标识；未知或受污染的 provenance 元数据分别降级为
  `unknown` / `null`，不回显原始字符串；
- 不把“索引可用”偷换为“正文可展示”：indexable 只可索引元数据，正文片段级字段不展示。

### 复核强化（已授权但无事实锚点）

`usage_rights=snippet/redistributable` 只表示**可以展示**，不表示孤立的
`status=extracted` 值已经被证据支撑。若字段缺少完整 `evidence`（非空 `chunk_uid`、
`locator`、证据句及有效 span），出口返回 `value=null`、`display="not_grounded"`、
`reason="extracted_field_missing_valid_evidence"`，且不返回 `evidence`。这避免授权路径把
无可回链来源的抽取值当作事实；新增
`test_authorized_extracted_field_without_evidence_is_not_factual` 锁定该行为。

### 回归测试（新增/强化）

- `test_indexable_blocks_value_display`：`json.dumps(view)` **不含测试正文句** + audit 存在 + evidence 不存在；
- `test_unknown_usage_rights_is_conservative`：value/evidence/pending_candidates 全部不返回，正文句与候选句不出现在序列化输出；
- `test_query_returns_fields_with_provenance_and_license`：snippet 场景保留完整 evidence（sentence/span）；
- `test_tool_run_does_not_leak_body_for_indexable`：Agent tool 输出同样不泄露；
- **复核强化（D05-REV）**：`test_indexable_does_not_leak_numeric_sentence`（`numeric_findings` 的 value 列表含原文句 → indexable 下不泄露、audit 可查）、
  `test_multiple_sources_indexable_do_not_leak`（多来源 matches 每项都不泄露）、
  `test_indexable_audit_metadata_is_fail_closed`（受污染的 `chunk_uid`/locator 不回显）。
  实测复核：`query_structured` 在 indexable 下序列化输出不含任何证据句/候选句（含 numeric_findings 与 matches 路径）。
