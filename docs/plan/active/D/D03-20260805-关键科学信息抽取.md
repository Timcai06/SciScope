## 2. 输入 / 输出 schema

**输入**：D02 可追溯 chunk（`data/admission/traceable/chunks.jsonl`），每条含 `paper_id`、`source`、`record_sha256`、`chunk_uid`、`locator`、`text`、`source_field`、`parser_version`。

**输出**（schema 版本 `structured-extraction/v1`）：

```jsonc
{
  "schema_version": "structured-extraction/v1",
  "paper_id": "PX-100",
  "source": "iflytek",
  "record_sha256": "<sha256>",
  "fields": [
    {
      "field": "study_population",            // study_population | study_design | main_result |
                                              // numeric_findings | limitations | conclusion
      "status": "extracted",                  // extracted | not_found | low_confidence
      "value": "…证据句…",                     // 非空字段才有值；无法定位/低置信留空
      "confidence": 0.8,                      // 0.8 强指示词 / 0.6 一般 / 0.4 回退候选 / 0 无
      "evidence": {                           // 每个非空字段必带 provenance
        "chunk_uid": "…",
        "locator": {…},                       // D02 定位（页码/文本范围/字段）
        "sentence": "…原文句…",
        "span": {"start_char": 0, "end_char": 42}
      },
      "candidates": ["…待审候选句…"],          // low_confidence/not_found 时供人工待审
      "reason": ""                            // low_confidence 原因（span_not_located / 回退等）
    }
  ],
  "non_empty_fields": ["study_population", "…"],
  "extracted_at": "…"
}
```

`numeric_findings.value` 为条目列表，每条含 `sentence`/`span`/`chunk_uid`/`locator`/`values[{number, unit}]`；字段级 `evidence` 指向首个条目。数值发现规则：**带单位或含小数**的量（孤立整数如页码不算），另收 `p<0.05` 类 p 值。

## 评审修订（2026-08，按复核反馈）

### HIGH-1：被篡改的 chunk 不再产出确定结果

- 新增 `chunk_uid_matches`：按 D02 生成公式（`stable_uid("trace-chunk", paper_id, source, record_sha256, chunk_index, chunk_type, page, text)`）
  重算 `chunk_uid`，不一致即来源链断裂 → 该 chunk **禁止参与抽取**，记入 `invalid_chunks`（含原因 `chunk_uid_mismatch`），不静默丢弃；
- 篡改测试重写为评审复现场景（旧 chunk 前注入伪造结果句、保留旧 chunk_uid）：断言结果**不能保持 `extracted`**，
  且伪造句不得成为任何字段值；
- `ExtractionResult` 新增 `invalid_chunks` 字段；`run_structured_extraction` 的 summary 新增 `invalid_chunks` 计数。

### HIGH-2：批处理按 (source, paper_id, record_sha256) 聚合

- 聚合键由 `paper_id` 改为 **(source, paper_id, record_sha256)**，不同来源的同名 paper_id 不再合并；
- 组内一致性防御：chunk 的来源/论文/哈希与组键不一致时单独计数为 invalid；
- 新增 `test_cross_source_same_paper_id_not_merged`：s1/P1 与 s2/P1 → `papers_processed=2`、输出两篇、字段不混。

### 中优先级（一并修复）

1. **确定性排序**：`extract_from_chunks` 先按 `(chunk_index, chunk_uid)` 排序，输入顺序不影响结果（`test_input_ordering_does_not_change_extraction`）；
2. **切句支持换行**：`_split_sentences` 把换行也作为句子边界，标题与摘要首句不再合并（`test_newline_splits_sentences`）；
3. **时间戳移到运行级 summary**：`structured.jsonl` 行不再含 `extracted_at`，相同输入输出确定（`test_structured_output_has_no_timestamp`；summary 含 `extracted_at`）。

## 5. 未运行项、风险与回退

- **未运行**：未调用任何在线 LLM；未做全量重建/embedding/GPU（2080 Ti 不可用，硬约束）；未接入真实讯飞数据与真实论文。
- **规则抽取的固有局限**：指示词表为最小集合（中英），覆盖真实语料时 recall 有限——这是**诚实边界**，字段级置信度与 `not_found` 会如实反映，不会编造；扩大词表属后续增强（D04 质量评估会给出字段级正确率）。
- **回退**：`structured_extraction.py` 独立于生产链，出现问题时删除模块与测试即可，不影响 RAG/检索/Agent；输出全部在受控原始区（`data/admission/structured/`），不进公开导出。
