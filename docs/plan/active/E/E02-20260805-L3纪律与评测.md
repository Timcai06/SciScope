## 1. 目标与改动概述

把 `verify_claim` 收紧为可复核的 L3 基线，补上一处违反硬约束的实现缺陷并补齐测试：

- **缺陷修复（硬约束 4，两轮）**：
  - 第一轮：`_coerce_judgements` 原先把未知 stance 标签静默改写为 NEUTRAL 且 `ok=True`。
    改为 fail-closed——任何非标准标签使 `judge_evidence` 返回 `ok=False`。
  - 第二轮（复核）：fail-closed **完整化**——空数组 `[]`、多余元素、缺失/空 stance、
    非对象元素一律整体拒答（`ok=False` + 可诊断 note），**不再用默认值填充**；
    `confidence` 缺失/不可解析默认 **0.0**（原 0.5 恰好等于聚合阈值 `>=0.5`，
    可能意外导出「部分支持/证据反驳」）。
- **note 语义修复**：原 `coerced N nonstandard labels` 统计错误，现返回可诊断原因
  （`reply length N != expected M` / `missing stance field` / `nonstandard stance label 'X'` / `non-object element`）。
- **NaN/Infinity fail-closed（第三轮，REVISE）**：Python `json.loads` 接受 `NaN`/`Infinity`，
  原钳制 `max(0,min(1,conf))` 会把它们变成 1.0，端到端可导出「强支持」。修复：
  judge 层 `math.isfinite(conf)` 检查，非有限值→整次 `ok=False`（note 含 `non-finite`），
  走「证据不足」回退；verify_claim 聚合层 `countable` 同样加 `isfinite` 防御
  （`inf >= 阈值` 为 True，原可漏过）。
- **测试补齐**：每项 L3 纪律现在都有正例与反例测试（见 §3 矩阵）。

  对照"，非主表；主表命令（`--gold gold_v1 --predictions …`）待正式金标准建立。
- **风险 3（测试数随工作区波动）**：360 passed 含 A 线未提交测试文件；
  复核时若测试集变化，以当时 `rtk make test-backend` 实际输出为准。
- **回退方式**：若 judge fail-closed 过于严格（真实场景 LLM 偶发非标准标签导致
  大量拒答），可回退为"未知标签记入 note 但保留 ok=True"并配 warning，但**不得**
  回到静默降 NEUTRAL；是否放宽须项目负责人决定。

### 8.2 正式双语主集（gold_v1）schema 与冻结规则

记录 schema（`build_stance_packets` 候选输入，与 `evaluation/stance/annotation.py` 对齐）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定唯一 ID |
| `claim` | 是 | 论断文本 |
| `evidence` | 是 | 待判定证据（原文 span/句） |
| `language` | 是 | `zh` / `en` / `cross` |
| `source` | 是 | 来源标识（论文/语料） |
| `domain` | 是 | 领域分层：`computer_science` / `biomedicine` / `materials_science` |

标注字段（双人独立）：`stance`（`SUPPORT`/`CONTRADICT`/`NEUTRAL`）、`evidence_sentence`（非 NEUTRAL 必须逐字且 ∈ evidence）、`qualification`、`notes`；
专家裁决字段：`adjudicated_*`（`reconcile_stance_annotations` 输出）。

**冻结规则（gold_v1）**：
1. 双人独立标注（不得互看）；2. 第三位领域专家只裁决分歧；
3. `finalise_gold` 校验（标签合法、证据句逐字、非 NEUTRAL 必须有句）；
4. **哈希冻结**并记录 split（train/dev/test 一次性切分，从训练/调参中排除）；
5. 冻结后不得修改；任何修订走新版本。
标注指南：`evaluation/stance/ANNOTATION_GUIDE.md`（既有，照此执行）。
