# E02b｜无法正式专家标注时的双语 Silver 替代收口

> 状态：`REVISE`（技术准入与可复现性已收口；正式双语 Gold v1 / 外部证明仍未具备）
> 日期：2026-08-10 ｜ 依赖：E02 L3 纪律、E02a SciFact 官方数据准入
> 诚实边界：本方案**不把机器翻译、LLM 共识、规则化对抗样例或开发夹具称为人工金标准**；不产生也不展示质量分数。

## 1. 可行替代路线

两位队友当前不能完成独立专家标注，故不伪造 `gold_v1`，改用两层互不混淆的资产：

| 层 | 资产 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| 英文 gold 锚点 | 官方 SciFact dev；`scifact_data.py` 的文件哈希、schema 与 rationale 准入 | 英文公开基准的来源、许可、复现实验输入已固定；有批准预测时可独立评分 | SciScope 中文能力、专家效果、真实用户成效 |
| 双语 silver | `bilingual_silver_v0.jsonl`（6 条）与冻结 manifest | 中文/跨语输入、原始 SciFact claim/doc/句索引、变换方式可审计；回归和模型间一致性可复现 | 人工标注一致性、accuracy、校准、国赛主表 |

Silver 每条都必须回链 `SciFact dev claim_id + doc_id + sentence_index + source_label`，运行时重新核对官方原文和 rationale；中文翻译与比较方向反转明确写为 `project_manual_unreviewed` / `unreviewed_silver`。这避免把“来源有 gold”偷换成“中文派生样本有专家 gold”。

## 2. 实现与 fail-closed 门禁

- `evaluation/stance/silver.py`：验证冻结 manifest SHA256、双语 pair、逐字证据句、来源 claim/doc/句索引和官方 rationale。任何内容/来源漂移均拒绝。
- `evaluation/stance/silver_eval.py`：默认仅准入；只有显式 `--allow-agreement` 且提供 A/B 两个完整预测文件，才输出模型间 `stance_agreement` 与三份 SHA256。
- agreement 路径不会用 silver `label` 评分，报告字段固定写明 `not_quality_score`；缺失/多余 ID、非三标签、未冻结输入一律拒绝。
- `bilingual_silver_v0.manifest.json` 的 status 固定为 `frozen_silver_not_gold`，usage 固定为 `regression_and_model_agreement_only`。

最小运行：

```bash
rtk summary python3 -m evaluation.stance.silver_eval
rtk summary python3 -m evaluation.stance.silver_eval \
  --predictions-a output/model_a.jsonl --predictions-b output/model_b.jsonl --allow-agreement
```

第二条命令只有在两个**已保存、可审计且彼此独立生成**的预测工件存在时才可运行；其 agreement 仅表示两个模型在同一输入上的一致程度，不能推导正确性。

## 3. 本轮关闭与未关闭的门禁

| 门禁 | 状态 | 证据边界 |
|---|---|---|
| SciFact 英文源可追溯、哈希/schema/rationale 准入 | ✅ | E02a 官方数据；不等于已跑模型分数 |
| 中文/跨语最小集的来源、变换、冻结和防篡改 | ✅ | 6 条 unreviewed silver，非大规模自动数据 |
| 同冻结输入的独立模型一致性可复现 | ✅（入口） | 需后续提供两个预测工件；无工件时不声称结果 |
| 英文公开锚点的模型真评分 | ⛔ | 仍需批准的预测、明确检索/模型配置和 E02a 评分入口 |
| 双语人工 Gold v1、双盲一致性和专家裁决 | ⛔ | 无两位独立标注者与领域专家，不能以 silver 替代 |
| L3 主表（Macro-F1、证据句、Brier/ECE） | ⛔ | 只能在正式 Gold v1 上计算并报告 |
| 国赛外部证明/真实场景反馈 | ⛔ | 仍依赖 E08 授权、联系人与外部反馈 |

## 4. E03 依赖结论

本方案与 SciFact 真评分共同关闭 E02 的**工程输入/来源技术门禁**，因此项目负责人可以启动 E03
数据库/API/MCP 三读集成；但 E03 只能标记工程集成结果。正式双语质量证明仍未具备，E02 不得写成
“L3 质量 PASS”，silver 的标签或 agreement 也不得进入质量主表。
