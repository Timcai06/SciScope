# 阶段计划标题

- 任务分配名：`代号-中文短名`
- 状态：`draft`
- 负责人：`待认领`
- 代码审核与最终验收：`待认领`
- 最后验证时间：`YYYY-MM-DD`
- 对应目标上游：[`../project/国赛目标说明书.md`](../project/国赛目标说明书.md)

## 目标

用一段话说明本计划结束后可以被验证的结果。

## 范围

- 本计划会修改或交付什么。

## 非目标

- 明确本计划不会提前锁定或实现什么。

## 前置事实与依赖

- 链接 canonical 文档、目标说明书和前置计划，不复制其全文；
- 关键事实表：每条给真实文件路径与行号，或可复现的验证命令。

## 验收条件

1. 可观察、可复现的验收条件。

## 实施步骤（原子任务）

1. 按依赖顺序拆分任务；每个原子任务包含：依赖、文件边界、可并行性、完成标准、
   验证命令/证据。不把候选方案写成已接受设计。

## 预期事实回写

| 稳定事实类型 | 目标文档 |
|---|---|
| 目标 / 成功度量变化 | `docs/project/国赛目标说明书.md`（须正式修订） |
| 项目方针 | `docs/project/charter.md` |
| 架构 / 接口 / 工具 | `docs/architecture/...`、`docs/developer/mcp.md` |
| 运行 / 交付 | `docs/operations/runbook.md`、`docs/release/...` |

## 验证证据

| 验收项 | 证据 | 结果 |
|---|---|---|
| 待验证 | 命令、测试报告、截图、日志或人工验收记录 | `pending` |

不得记录密钥、未发布数据或无法复现的口头结论。

## 风险与外部阻塞

- 风险、触发条件和回退方式；外部依赖（数据、算力、标注人员、外部系统）单独列出。

## 收尾检查表

- [ ] 验收条件均有证据，失败项已明确转入后续计划；
- [ ] 稳定事实已经回写到 canonical 文档；
- [ ] 重大取舍已经记入目标说明书或决策文档（如需要）；
- [ ] 临时方案和过期过程记录已删除或压缩；
- [ ] 计划已移入 `completed/` 并更新 `docs/plan/README.md` 与 `docs/plan/active/README.md`。
