\section{工程交付设计（国赛双轨）}

\begin{designbox}{交付原则}
最终交付不是孤立 PDF, 也不是只在开发机上的 demo。它是可复现工程包：
数据处理代码生成分析资产, 服务层消费资产, 证据层提供 stance/争议能力,
MCP 把能力暴露给外部 agent, Go TUI 演示完整工作流。提交配套"评委视频 + 硬件清单"双轨。
\end{designbox}

\subsection{演示与复现双轨}

\begin{plainbox}
\begin{itemize}
  \item \textbf{评委视频}: 本机全量 + OpenCode 调用的黄金脚本（约 6--8 分钟）, 综合评委 10 分钟内建立信任。
  \item \textbf{硬件清单}: CPU/RAM/磁盘、PostgreSQL/pgvector、模型路径、耗时量级、关键命令,
        说明全量可复现的门槛。
  \item \textbf{文档复现}: runbook 逐步: 安装 $\rightarrow$ 起库 $\rightarrow$ 加载 $\rightarrow$ 启动 $\rightarrow$ 黄金脚本。
  \item \textbf{不承诺}: 不把 hosted 小库当国赛主演示; 现场环境不允许全量时以视频为能力举证。
\end{itemize}
\end{plainbox}

\subsection{黄金演示脚本（约 6--8 分钟）}

\begin{enumerate}
  \item C 开场: 文献要素治理 $\rightarrow$ 证据服务。
  \item 规模一屏: 运行库论文/chunk 与报告口径一致。
  \item B 基线: 真实问题 $\rightarrow$ `[n]` 证据问答 $\rightarrow$ 证据卡。
  \item A L3: 正论断 / 反论断 / 限定冲突 / 证据不足。
  \item 争议地图: 列表读到刚写入的矛盾 claim。
  \item OpenCode 调用: MCP verify\_claim + disputes resource。
  \item 收束: 三创新点 + 一句诚实边界。
\end{enumerate}

\subsection{验收口径}

\begin{enumerate}
  \item 本机全量库可起, 运行库数字与报告口径一致。
  \item stance 正反论断不同判; 低置信给"证据不足"; 回退不出现"强支持"。
  \item 争议地图 API / Agent tool / MCP resource 三条读路径同一 claim 可读。
  \item OpenCode 真实调用过一次, 有日志/录屏产物。
  \item 所有对外结论都能追溯到数据资产或检索证据。
\end{enumerate}
